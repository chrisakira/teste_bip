# BIP App — Backend Module

Concise documentation for the Spring Boot backend implemented under the `backend-module` folder.

## Overview

- Java + Spring Boot REST API that manages `Beneficio` resources and supports a transfer operation between two benefits.
- Designed to be simple, readable and easy to run locally for development or assessment purposes.

## Requirements

- Java 17 (target). The project runs on newer JVMs (used successfully on Java 25); when using Java 25 some test tooling (Mockito/ByteBuddy) requires an extra flag (see Notes).
- Maven 3.6+

## Build

From the workspace root or `backend-module` directory:

```bash
# build (includes tests)
mvn -Dnet.bytebuddy.experimental=true clean package
```

You can also run the app directly in development:

```bash
cd backend-module
./scripts/run-backend.sh
# or
mvn spring-boot:run -Dnet.bytebuddy.experimental=true
```

## Helper scripts

- `scripts/install-deps.sh` — helper to install Java/Maven on supported systems.
- `scripts/run-backend.sh` — builds and runs the backend (dev-friendly wrapper).
- `scripts/run-tests.sh [unit|integration|all] [-q|--quiet]` — run tests:
  - `unit` — run only unit tests
  - `integration` — run only integration tests
  - `all` — run all tests (default)
  - `-q` / `--quiet` — pretty summary output (shows totals and coverage percent)

Examples:

```bash
./scripts/run-tests.sh -q            # run all tests, pretty output + coverage
./scripts/run-tests.sh unit -q      # run only unit tests
./scripts/run-tests.sh integration  # run integration tests with normal Maven output
```

## API Endpoints

Base path: `/api/v1/beneficios`

- `GET  /api/v1/beneficios` — list all benefits
- `GET  /api/v1/beneficios/{id}` — get benefit by id
- `POST /api/v1/beneficios` — create new benefit (JSON body)
- `PUT  /api/v1/beneficios/{id}` — update existing benefit (JSON body)
- `DELETE /api/v1/beneficios/{id}` — delete benefit
- `POST /api/v1/beneficios/transferir` — transfer value between benefits. JSON payload example:

```json
{
  "origemId": 1,
  "destinoId": 2,
  "valor": 100.00
}
```

HTTP responses are conventional: `200` success, `201` created, `400` bad request, `404` not found, `500` server error.

## Data Model (entity: `Beneficio`)

- `id` (Long)
- `nome` (String)
- `descricao` (String)
- `valor` (BigDecimal) — monetary amount
- `ativo` (boolean) — active flag
- `version` (Long) — JPA optimistic locking

The transfer operation uses pessimistic locking in the repository to avoid concurrent consistency issues and validates sufficient balance before committing.

## Curl Examples

Assuming the app runs on http://localhost:8080, here are quick curl examples.

List all benefits

```bash
curl -sS http://localhost:8080/api/v1/beneficios
```

Get by id (replace 1)

```bash
curl -sS http://localhost:8080/api/v1/beneficios/1
```

Create a new benefit

```bash
curl -sS -X POST http://localhost:8080/api/v1/beneficios \
  -H "Content-Type: application/json" \
  -d '{"nome":"Novo","descricao":"Teste","valor":300.00}'
```

Update a benefit (replace 1)

```bash
curl -sS -X PUT http://localhost:8080/api/v1/beneficios/1 \
  -H "Content-Type: application/json" \
  -d '{"id":1,"nome":"Atualizado","descricao":"Alterado","valor":350.00}'
```

Delete a benefit (replace 1)

```bash
curl -sS -X DELETE http://localhost:8080/api/v1/beneficios/1
```

Transfer between benefits (replace ids)

```bash
curl -sS -X POST http://localhost:8080/api/v1/beneficios/transferir \
  -H "Content-Type: application/json" \
  -d '{"origemId":1,"destinoId":2,"valor":100.00}'
```
